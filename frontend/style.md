# ShopSteward 前端视觉规范

2026-09-07 · 暖光磨砂风格。本文件记录当前已实现的视觉语言，供后续前端迭代沿用。修改界面前先读本文件，再核对对应组件和 `app/assets/css/shop.css`；具体数值以样式源码为准，显著风格调整需同步更新本文。

## 1. 产品气质与信息层级

ShopSteward 是店主的日常经营助手。页面应安静、清晰、有层次，让用户先知道是否需要自己决定，再理解现金与库存影响、确认对象和后续进展。

- 默认进入“今日”。待决定事项在主工作区优先呈现；正常等待、执行进度和历史记录各有清楚的位置。
- 一屏围绕当前任务组织，避免把所有数字、说明和入口切成大小相同的独立卡片。先用对齐、留白和字号区分，再用分隔线；只有不同交互层才使用不同表面。
- 经营事实、预测、系统推荐、用户选择、采购受理与实际到货必须可区分。视觉精简不能隐去数据时点、重要条件、错误或确认边界。
- 经营概览作为次级入口，不替代“今日”的决策主线。

## 2. 材质与颜色

采用暖白到浅蓝的环境底色、稳定的正文表面与磨砂控制层。苹果式质感是设计参考；当前为原生 CSS 的 Web 近似，不是苹果原生 Liquid Glass，也不依赖 WebGL 或 SVG 折射运行库。

| 用途       | 当前基准                       | 使用原则                                                         |
| ---------- | ------------------------------ | ---------------------------------------------------------------- |
| 正文       | `#28343e`                      | 深灰蓝，避免纯黑与大面积低对比灰字                               |
| 辅助文字   | `--muted: #626d77`             | 正文说明仍须清晰；更小字号只用于来源、时间等次要信息             |
| 操作蓝     | `--blue: #2869c4`              | 主要操作、选中态及可点击入口；不把所有数据染成蓝色               |
| 分隔线     | `--line: rgb(67 80 100 / 12%)` | 轻量组织同一表面中的信息                                         |
| 环境底色   | `#f6f3ec → #eef2f7 → #ebf0f1`  | 暖光在左、冷光在右，保持静止；不使用持续流动或高饱和极光背景     |
| 正向状态   | 柔和绿                         | 只表示已核实状态或满足已定义条件，不暗示收益、绝对安全或执行成功 |
| 待处理状态 | 琥珀色                         | 与明确文字说明共同使用，不仅靠颜色表达异常                       |

磨砂集中在顶部导航、固定浮条、轻操作和浮层背景。正文、表格与金额不叠多层高透明玻璃。主要 CSS 机制：半透明填充、`backdrop-filter`、细白边、内侧高光、短接触阴影与柔和外阴影。禁止用粗白描边、强烈外发光或不断扫动的高光代替材质。

当前控制层约使用 20–30px blur、125–140% saturation；`.glass` 使用 28px blur。一个页面沿用已有材质，不为每个区块另外发明一组玻璃参数。

## 3. 字体、数字与间距

- 字体沿用系统栈：Apple 系统字体／SF Pro Display、Segoe UI、PingFang SC、Microsoft YaHei、sans-serif。无远程字体请求。
- 桌面正文通常15px；主标题32–40px；决策标题26–34px；主影响数字36px；现金余额42px。小屏主标题约26px、决策标题25px、影响数字24px。
- 金额及状态数字用 `tabular-nums`；金额、数量、时间沿用 `app/utils/presentation.ts`，不在样式组件中重新定义业务单位。
- 12–13px用于辅助说明；11px仅用于紧凑元信息，不能承载决定是否采购的主要事实。
- 核心节奏以4px为步长：8／12px用于相关控件，16／24px用于组内层次，26／30px用于主要表面内边距。保持连续的基线和列宽，避免为凑首屏压缩可读性。

## 4. 页面布局

当前 `.app` 最大宽度1660px，桌面工作区横向内边距48px。顶部 `.app-header` 承载品牌、三项主导航和店铺入口；正文中的工具条承载来源与设置等辅助操作。

主要内容为连续的大工作区，桌面 `.content-grid` 使用 `minmax(0, 1fr) 284px` 两列、34px间距：左侧决策／跟进／记录，右侧当前经营事实。右侧通过细分隔线组织，不重复包成一组大卡片。

- 大工作区圆角约28–32px；导航及浮条约24–28px；操作按钮约16–18px。圆角应随控件尺寸调整，避免所有元素统一成大胶囊。
- 无待办、跟进详情及资料入口尽量融入同一表面。错误信息可单独强调，但不能覆盖原数据来源和可恢复入口。
- 页面允许自然滚动。固定控件必须有底部内容余量和滚动定位余量，避免挡住确认按钮、表格末行或输入框。

## 5. 交互控件与动效

**采购选项：** 用一条浅色槽承载候选，以滑动的磨砂底板表示当前选择。系统“推荐”标识独立存在，不能随用户改选而改写推荐。当前滑动使用 CSS `:has()` 与 transform，约300ms；金额直接更新，不做翻牌或滚动计数。

**主按钮：** 一处当前主要动作，使用细腻蓝色渐变、顶部高光和轻阴影；hover仅轻微提亮，按下缩放约0.98。最低高度46px。按钮文字须说明具体对象，例如“核对40件采购”，视觉反馈不替代后端回执。

**次按钮：** 暖白磨砂、低对比边缘，与主操作有明显权重差异。链接保持清楚的文字／图标提示，不把危险或提交操作伪装成普通导航。

**固定浮条：** 位于视口底部22px，当前只承载已有今日、持续跟进、经营记录和联调面板入口。它不是预设演示快照播放器；不能通过前端改写经营时间、现金、库存或订单。

**弹层：** 沿用原生 `dialog`，桌面约620px宽，最高90dvh；背景轻度模糊，正文稳定且不透明。入场约260ms，轻微位移和缩放。保留Escape、外部点击、操作中关闭限制和关闭后的焦点返回。

全局缓动 `--ease: cubic-bezier(.22, 1, .36, 1)`。通常180–300ms，避免夸张弹跳、磁吸追鼠、数字动画、视差滚动或不间断装饰动效。后台状态变化不应触发整页重新入场。

## 6. 响应式与可访问性

- 821–1200px：缩减工作区边距、侧栏列宽和导航间距；不隐藏重要数值。
- ≤820px：顶部桌面导航和桌面浮条收起，使用移动端底部导航；经营事实摘要前置，正文单列。
- ≤580px：保留采购选项的原有展开机制，使用纵向选项；滑动背景改为清楚的独立选中样式。输入字号避免过小，操作区域至少44px。
- 保留清晰的 `:focus-visible`。选中状态同时有文字、形状或语义属性；禁用状态沿用原有条件。
- `prefers-reduced-motion` 关闭动效；提供减少透明度和不支持 backdrop-filter 的实色回退。CSS回退不等于完成所有浏览器的实机验证。
- 打印时隐藏固定导航和操作层。不得出现横向整页溢出；宽表可以在自己的容器内横向滚动。

## 7. 代码与迭代约定

基础视觉样式在 `app/assets/css/shop.css`，经营概览扩展在 `app/assets/css/overview.css`；新增组件优先复用现有变量、图标和控件类。修改已有规则，不在文件末尾持续叠加互相覆盖的主题补丁。当前使用已有Lucide图标资源，避免混入另一套图标风格。

纯视觉迭代默认不修改 `useShop.ts`、API工具、生成类型、server代理、确认／幂等／业务状态逻辑及其他模块。新增功能需先确认现有契约和授权范围；原型中的模拟逻辑不能迁入生产前端。不要为了一个装饰效果安装整套组件库。

每次交付至少检查：

1. 桌面和手机的真实浏览器画面，包含当前任务、无数据／错误及主要弹层；用固定状态比较，避免把数据差异当视觉差异。
2. 固定浮条不挡住主操作，长名称／金额／时间不溢出，键盘与选中态可见，减少动效生效。
3. 运行与变更相称的类型、构建和接口契约检查；核对Git差异，确认未混入业务或后端改动。
4. 记录哪些是实际API结果、哪些是隔离浏览器样例。截图或动画完成不代表采购、到货、模型或完整产品验收完成。

## 9. 经营概览的图表与材质（2026-09-08）

经营概览延续暖光磨砂，不成为默认首页。进入入口在经营事实区域与浮条辅助区；现有建议卡、自然语言输入和逐笔确认保持原流程。正常首屏只保留金额、数量、必要状态、经营时点和详情入口，口径说明收进可点击详情；过期/未知/不一致仍就地可见。

采用非等分布局：左侧资金置于连续环境背景，右侧销售为主要稳定表面，下方库存较宽、到货较窄。现金主数约60–82px，销售/库存数字约34–44px；数字不滚动计数，长数允许换行。主要区块标题18–20px，图轴13px。手机先看资金与库存，再看销售和到货，保持自然滚动和底部导航余量。

ECharts负责数据几何；渐变阶梯线、低强度辉光、双色纹理柱和焦点提示表达读取位置，库存实色/斜纹明确区分在库/在途。不得根据图片手抄比例、抬高零柱、平滑虚构销售趋势、用装饰纹理冒充预测或数据状态。现金图是事件检查点的余额，不代表等间距时间；没有现金变更时显示简洁空态。

正常动效以180–300ms的选中底板和数据更新为主，图表首次入场约550ms；后台刷新不重新播放整个页面。重排时图表直接适应容器尺寸；CSS限制瞬间溢出，测试核对SVG宽度确实更新，不能只靠裁切掩盖未重排图。降低动效时关闭过渡，减少透明度时使用实色表面。

图表引擎延迟下载。当前ECharts独立包压缩前约546kB，gzip约186kB，会触发构建chunk体积提示；不得通过提高阈值掩盖提示。已用生产网络检查确认今日不加载该包，进入概览才加载。进一步性能优化需以实际设备证据决定。
