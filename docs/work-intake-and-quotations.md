# 自然语言事项与持久报价处理

本实现对应[2026-09-29开发交接](https://mvtrg57bfb7.feishu.cn/wiki/Did2w9FHBitMx5kXY6ycEtBynbc)的N1—N4与Q1—Q4。沿用单商品、指定供应商的业务边界；建立委托需要用户接受条件，每笔采购仍走原审批流程。报价整理不修改经营账本或正式供应商报价。

## 启动

使用仓库锁定依赖，在目标环境的backend目录运行`python -m alembic upgrade head`，数据库版本须为`0015_quotations`。迁移只新增报价原件和计算结果表，报价规则复用现有用户/店铺知识及修订记录。

报价上传、字段纠正、计算、规则保存及下载由已有业务API提供，不依赖模型。启用自然语言办理时，在API与事项worker的环境中设置：

```dotenv
WORK_PROCESSOR_ENABLED=true
AGENT_BASE_URL=https://api.openai.com/v1
AGENT_MODEL=gpt-4.1-mini
AGENT_API_MODE=chat_completions
AGENT_API_KEY_FILE=/private/config/model-key.txt
```

密钥文件由部署环境提供，不提交仓库或传给模型上下文。也可使用现有适配器支持的Responses模式。随后在backend目录独立启动：

```bash
python -m app.worker --profile work
```

此进程读取已保存事项，通过原用户权限调用业务工具；`--profile business`继续承担业务调度，`--profile agent`继续承担已有Mission Agent。三个进程分别启用。界面的`processor_available`是配置声明，不是模型可用性或进程存活证明；部署后应检查实际处理结果。Mac mini的原日常启动器默认不启动模型worker。

## 处理与恢复

新事项与补充消息保存在原WorkItem/WorkMessage中。处理者复用领取租约、版本校验和幂等回执；每个工具写入和最终回传均重新核对租约、用户权限与事项版本。新增要求或停止分析使旧处理失效。成功业务动作不会因中止回答自动撤销，重试通过持久工具回执避免重复动作。

模型解释意图、选择受限工具和提出必要澄清；库存现金、数量计算、方案修订、暂停回执和报价结果均来自业务工具。比较不修订方案；创建委托前先展示条件，接受后才建立Mission。现有预测只对其实际期间有效，人工需求只能用于明确标记的试算。

## 报价文件与规则

文件与事项关联，服务端再次验证UTF-8 CSV、200KB与1—100条记录边界。支持现有中英文模板列。原件以内容哈希保存，纠正与每次计算生成可追溯结果版本。单件价由Decimal计算；按件价格保留，箱/包按包装数换算。缺依据行保留待补，不支持币种不进入单价排名。

“仅本次”只改变该结果；明确保存长期规则后，当前用户与店铺的新事项可以复用。规则采用封闭的排序选项，保留来源及版本，不能改变数值换算、现金底线或采购权限。每个处理固定所用规则版本，后续纠正不会重写已有结果。原件与结果下载均通过事项权限校验。
