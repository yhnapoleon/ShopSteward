# 任务工作区前端 · 第一阶段

2026-09-08，Mac mini；验证基于 `jeffrey / 5f57a3b` 的提交前工作区；后续发布状态见仓库交接与GitHub。用户在本轮确认“任务卡片 → 独立任务页 → 常驻 Agent 工作区”，以及“后端确定状态、运行时上报工具、Agent 解释工作”的职责分离。本报告只说明当前交付，不将下一阶段视为已经实现。

## 已实现的体验

- 今日入口显示真实任务卡，进入 `/?view=task&mission=<mission_id>&store=<store_id>`；全局 Agent 入口可直接进入该任务的工作区。任务详情与首页共用 Mission 身份，刷新恢复原任务；不存在或无权读取的任务不会静默替换为另一项任务。
- 桌面为方案/事实/跟进/历史与 Agent 工作区双栏；手机在“方案与进展”和“Agent 工作”之间切换，事实摘要在采购方案前。任务页保留原采购审批弹层、版本/hash/幂等机制和原确认恢复。
- 会话状态从卡片生命周期中移出，由页面唯一同步器管理。返回今日、进入概览再回来不丢未发送草稿；身份、权限、店铺、任务变化清空旧作用域，迟到响应不改新任务。
- 消息使用 `after_seq` 增量合并，以消息 ID 去重。发送有本地回显；结果未确认时沿用原幂等键重试。自适应输入支持中文输入法、Enter 发送与 Shift+Enter 换行；上滚阅读时停止自动跟随。
- 工具记录来自实际 RunView.tools，按 `(run_id, invocation_id)` 区分调用，同名工具重复调用不会覆盖。可回看某条历史回答所属 run；历史过程不会将用户定位到当前方案冒充历史结果。工具错误保留，整轮成功不抹掉失败子步骤。
- 展示公开的排队、运行、等待补充、成功、失败、停止状态。断开进度同步时停止正常忙碌动画。失败或取消后仍刷新业务记录，不能推断此前全部工具均未生效。
- 引用保留文档版本、检索版本、片段、定位和校验字段；只称为“本轮获取的来源”。没有原文片段时明确说明，没有伪造逐句引用或页码。
- 方案变化回执来自实际读取的前后两个版本，不解析模型文字生成业务字段。仅试算不改变现金；经营事实与待确认方案版本不一致时显示“方案待更新”。用户明确结束且没有未决采购/当前 Agent 工作时，调用已有 complete 接口，保留历史。

## 视觉与依赖

沿用暖白浅蓝、系统字体和现有 Lucide 图标。新增 `tasks.css` 组织任务页样式；Motion for Vue 用于布局与页面进入，原生 CSS 表达真实状态和新结果高亮，减少动效时关闭循环与位移。任务详情取消重复底部浮条，避免挡住审批按钮；全局主导航和手机导航保留。

新增依赖为 `motion-v`、`markdown-it`、`dompurify`，版本由 pnpm-lock.yaml 锁定。没有搬入整套 UI 主题。Markdown 关闭原始 HTML，清理输出仅允许阅读元素；不加载模型图片、表单和脚本，外链限制协议并在新页打开。服务端身份代理和后端契约未修改。

## 已发现并处理的问题

- 独立任务页初版遗漏经营提醒入口；已接回原提醒与知晓流程。
- 刷新时采购查询断开会让任务暂不可读；现在仍保留原确认查询入口，恢复后回到原任务。
- 新 Agent 入口使桌面头部换行，旧底部浮条遮住审批按钮；已调整头部栅格并移除任务页重复浮条。
- 手机长对话使业务信息过远；改为两种内容切换，保留共享状态与事实摘要。
- 切换经营环境原先无条件返回今日，影响概览；现在只退出失效的任务详情，概览继续显示新环境。
- 本机事件重规划有排队延迟：追踪中经营状态已到 v6，但界面最初只能取得基于 v5 的零采购方案；后端随后生成 v4 方案，建议追加20件。前端新增显式等待状态；SC01异步追加断言允许90秒等待。此调整不声称后台达到性能指标，也没有改后台队列或清理既有任务。

## 后续边界

1. 当前接口只记录工具返回后的摘要，没有工具开始事件、实时参数、耗时或完整试算结果；首期仅展示真实完成记录与整轮运行状态。下一阶段需补可回放的工具生命周期事件、事件游标和流式代理，再显示某一步“正在读取/试算”。
2. 精确证据片段、独立试算成果卡、持久前后差异还需要公开展示 DTO；当前消息引用定位与实际方案版本先承接。
3. 语音、流式正文、通用多任务并发未实现。仍遵守同店同商品一项未结束 Mission 的现有约束。
4. 未发送草稿保留于当前页面会话中的跨视图切换，刷新不会恢复草稿；持久消息和任务可从后端恢复。
5. 本机真实模型仍关闭；前端运行不等于真实 Agent 或完整 A-01/L-01 已验收。
