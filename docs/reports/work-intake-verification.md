# 用户主动事项：实现与验证

2026-09-09，基于jeffrey / 919bcde。本报告记录提交前冻结的实现和验证；发布状态以PR与Git为准。未修改飞书。用户本轮确认只做前后端承接，意图分类、LangGraph编排、模型分发和预测留给AI接入方。

## 本轮交付

- “交给我一件事”是真实输入入口。没有备货任务也可保存请求，形成持久事项卡片。
- 今日、持续跟进、经营记录与事项工作区关联同一记录。支持受理、处理中、待补、结果、阻塞、停止及恢复；咨询交付与备货完成分开。
- 对话追加、原请求重试、结果下载和历史回读。处理中补充会使旧租约/结果失效；服务中断后可重新领取。
- 服务身份可取得真实店铺、商品、经营状态及已有Mission上下文，并回传追问、进度、结果、已有任务关联或待接受的备货条件。未实现意图分类、模型调用、预测或报价算法。
- 同一用户同一Mission关联一张规范事项卡。归并保留原消息，原链接仍可解析；关联后复用原任务工作区、方案、逐笔确认与回执。此前Mission Agent对话有独立历史入口。
- 用户显式接受跟进条件才调用原create_mission；不能凭模型文字采购。模拟更新明确标记，不能用于创建真实备货委托；production拒绝模拟更新。

业务逻辑、接口、数据归属与待接入范围只在[模块说明](../../backend/app/work_items/README.md)维护。本报告保存验证证据，不另复制实现规范。

## 发布前按本轮约定复核（2026-09-09）

| 本轮约定 | 实现与验证结论 |
|---|---|
| 自然语言入口先接住一件事 | 用户原话持久保存，首次丢响应重试只建一次；没有分类器或模型时明确等待接入 |
| 同一卡片贯穿各入口和状态 | 今日、记录、工作区读取同一事项；已有Mission归并后旧链接仍可用 |
| 对话、进度、结果和恢复 | 多轮澄清、运行中改口、过期处理拒绝、结果下载、API重建回读已验证 |
| 保留现有备货能力与护栏 | 用户接受条件才建Mission；原采购审批、资金和回执逻辑未改，回归通过 |
| AI部分保持开放 | 外部服务领取上下文并回传结果；本轮未实现分类、LangGraph编排、预测或报价算法 |
| 模拟与真实结果分开 | 模拟标识随原结果保持，后续追问不能抹去标识，模拟提案不能建立真实Mission |
| 文档对应实际实现与待办 | 模块、架构、数据、API、前端/后端和交接均已说明当前能力与后续AI接入边界 |

复核补修：撤权后的立即重试循环；单个失效链接误清全部事项；结果未知时新操作覆盖原请求；断线恢复后旧错误未清；列表切换误移除上一事项；旧模拟结果被后续回传重标；撤权用户占据处理队列；已关联事项重复提出新Mission；跨场景迟到关联；正常身份能力标识替代对OpenAPI文档的依赖。读取复用既有只读一致性事务。没有扩大模型或采购权限。

**复核后的最终验证：108项相关后端/Agent、29项固定生产构建前端、1条关闭OpenAPI文档的真实HTTP/PG/生产浏览器链通过，均无跳过。** 其中新增后端11项事项测试、前端4项事项边界测试；95/25等上方数字保留初次交付时点，不与本次累加。迁移check、Ruff、类型/构建及生成契约通过；远端Windows CI和合并状态由PR提供独立证据。

复核修补阶段曾出现一个重试按钮模板编译问题，导致开发热更新预览中两项旧UI检查失败；已改为具名处理函数，随后固定生产构建29项全部通过。该失败不算通过，也不构成当前版本未解决问题。
