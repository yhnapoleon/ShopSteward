# ShopSteward 前端使用说明与改进建议

体验日期：2026 年 10 月 18 日

体验范围：本地示例店铺的电脑端界面，面向第一次使用软件的人。

这个软件帮助店主查看库存和现金、比较补货方案，并跟进采购和到货。AI 可以查询、解释和协助试算，每笔采购仍需要用户确认。

我的体验结论是：目前已经区分了待确认事项、跟进进度和历史记录。下一步应优先让新用户看懂“从哪里开始、当前做到哪一步、接下来该做什么”。

## 新用户应该怎样使用

1. **先确认正在使用哪家店铺。** 查看页面顶部的店铺名称。没有店铺数据时，点击“创建示例店铺”；SC01 是预设的模拟经营场景，供体验使用，不会向真实供应商下单。
2. **想查询或咨询，点“交给我一件事”。** 直接输入需求，例如“请查询当前库存和现金”。需要补充信息时继续回答，结果和对话会保存在同一事项中。
3. **想比较补货数量，点“先试算补货”。** 选择商品和供应商，填写希望至少保留的现金、要比较的数量，再点击“比较并保存结果”。例如比较 0、20、40 件，0 表示不补货。试算会保存结果，但不会直接采购。
4. **需要持续跟进时，确认建立备货委托。** 核对商品、供应商和现金底线等条件，再接受委托。建立委托只是让系统持续检查；有待确认的采购方案时，还需要另外确认具体采购。
5. **回到首页看待办，在详情里跟进结果。** “需要你拍板”放待确认事项，“系统在盯”放后续进展。已经采购的订单，在“采购与到货”查看受理和到货情况；过去的结果到“经营记录”找。

### 常用入口怎么选

| 我想做什么 | 去哪里 |
|---|---|
| 看今天要处理什么、店铺还有多少钱和多少货 | 今日 |
| 继续查看已经交给系统的事 | 持续跟进 |
| 查以前的结果、采购决定和账目 | 经营记录 |
| 问某项备货任务为什么这样推荐 | 打开该任务，在任务对话里追问 |
| 管理资料或整理供应商报价 | 文档中心、整理一份供应商报价 |

需要分清：**保存结果、建立委托、确认采购是三个不同动作。** “回答完成”或“结果已出”也不代表货物已经买到、已经到货。七日预测需要单独启用；本轮环境中该功能尚未启动。

## 建议的新手指引流程

建议首次进入时提供“跟着做一次”的引导，用一次补货试算带用户认识软件。下面是拟新增的交互和提示文案，目前尚未实现。

**整体路线：认识用途 → 选择店铺 → 看懂库存和现金 → 做一次试算 → 分清确认动作 → 找回结果。**

| 步骤 | 页面提示与用户操作 | 完成标志 |
|---|---|---|
| 1 认识用途 | 欢迎提示：“这里可以查看店铺的钱和货、比较补货方案，并跟进到货。我们先做一次不会下单的试算。”提供“开始体验”和“稍后再说”。 | 用户主动选择开始；跳过也能正常使用软件。 |
| 2 选择店铺 | 高亮店铺选择处：“先确认你在看哪家店铺。”已有店铺就继续使用；没有数据时，引导用户点击“创建示例店铺”，说明它使用模拟数据。 | 当前店铺名称和经营数据成功显示。已有店铺时不要求重新创建。 |
| 3 看懂钱和货 | 高亮“可用现金”“在库”“采购在途”：“可用现金是现在能使用的钱；在库是店里已有的货；在途是已采购但还没到的货。”引导用户找到这三个数。 | 用户点击“我找到了”，再进入下一步。 |
| 4 做一次试算 | 高亮“先试算补货”：“选商品和供应商，设置至少留下多少钱，再比较买多少件。”示例比较 0、20、40 件，解释 0 是不补货；由用户点击“比较并保存结果”。 | 成功显示并保存比较结果。若某个数量不满足现金或起订条件，说明原因，不把它显示成系统出错。 |
| 5 分清后续动作 | 在结果旁提示：“你刚才只做了比较，还没有采购。建立备货委托，是让系统继续检查；确认采购，才会提交具体采购。”展示这三个动作的关系，不要求用户在引导中下单。 | 用户明确知道本次操作只保存了试算结果。 |
| 6 找回结果 | 高亮“经营记录”，引导打开刚才保存的试算：“关掉页面后，也可以在这里找回结果。”结束时提供“开始自己使用”，并提示已有事项可到“持续跟进”查看。 | 用户能重新打开结果，完成引导。 |

### AI 咨询作为可选体验

完成基本流程后，再介绍“交给我一件事”：“不想先填表，也可以直接说你的需求。”提供示例问题“请查询当前库存和现金”，由用户确认发送，回答后展示继续追问的位置。

如果事项助手没有启用，说明“AI 咨询暂未启用，你仍可以使用补货试算”，允许跳过。新手不需要为了完成引导先理解 API Key、模型或后台服务。

### 引导交互的基本要求

- 每次只讲一个操作点，显示进度，例如“第 3 步，共 6 步”；支持上一步、下一步和退出。
- 创建店铺、提交试算或发送问题时，由用户点击真实操作按钮。等待结果成功后再继续；失败时保留已填内容，说明原因并提供重试。
- 不自动建立备货委托或确认采购；不把“点击下一步”当作业务授权。
- 引导结束或跳过后，可以从“设置”里的“重新查看新手指引”再次进入。已有结果时优先复用，不要求重复创建店铺和试算。

## 建议优先修改的地方

下表是本轮体验后的改版建议，不代表已经实施。P1 建议先做，P2 可以随后完善。

| 优先级 | 当前体验中的疑惑 | 建议修改 |
|---|---|---|
| P1 | 首页有多个入口，新用户需要自己判断从哪里开始。 | 首次进入显示简短引导：“选店铺 → 提需求或做试算 → 看结果”。为两个主按钮各加一句用途说明，并提供可点击的示例问题。 |
| P1 | “备货委托”“在途”“SC01”及英文商品名、供应商编号增加理解成本。 | 首次出现时补解释，例如“备货委托：让系统持续检查补货需求”“在途：已采购但未到货”。示例商品和供应商用中文名称，编号放到详情里。 |
| P1 | 同一备货详情里有“Agent 对话”和“事项对话”，容易不知道在哪边继续问。 | 默认提供一个清晰的“继续咨询这项任务”入口；确需保留两类对话时，用一句话解释用途，并突出当前正在延续的对话。 |
| P1 | 已有“等待到货”等提示，但从当前状态到下一步操作，还需要用户自己联系起来。 | 每个阶段固定显示“当前状态、系统在做什么、你可以做什么”。用流程条区分试算、建立委托、采购确认和到货；示例订单旁说明如何通过演示控制推进模拟时间。 |
| P2 | 试算数量要求用逗号输入，商品和供应商信息也偏技术化。 | 提供数量选项或可增删的数量标签，保留手动输入。给现金底线加例子：“至少留下 300 元用于经营”。提交后突出花费、剩余现金和缺货影响。 |
| P2 | 预测服务未启动时，首页仍展开较多输入项和不可用控件。 | 默认收起不可用功能，只保留“预测暂未启用，不影响库存查询和补货试算”的说明；面向管理员的配置帮助放到次级入口。 |
| P2 | 页面同时出现经营时点、同步时间和回答中的数据时间，时区与含义不容易比较。 | 时间统一按界面选定的时区显示，并明确标注“模拟经营时间”“最近同步时间”“回答生成时间”。来源详情保留原始时间，便于核对。 |

本轮建议先完成首次引导、常用术语解释和对话入口说明。这些修改直接影响用户能否开始操作，也比较容易通过下一轮体验验证。

## 怎么验证修改是否有效

建议邀请 3 名从未用过软件的同学，在不提前讲解的情况下完成以下任务：

1. 找到当前店铺的库存和可用现金。
2. 比较补货 0、20、40 件，并说明试算是否已经下单。
3. 找到一项已有采购，说明它是待确认、已采购还是等待到货，以及下一步该做什么。

记录每个人第一次点击哪里、在哪一步停住、是否需要提示，以及是否把试算误认为采购。优先修改多人共同卡住的位置；完成速度可以作为参考，但应先保证理解和操作正确。

## 本轮体验边界

本轮查看了首页、持续跟进、经营记录、备货详情和试算表单，结合此前的创建示例店铺与 AI 查询体验整理。没有提交新的试算或采购，也未完整体验文档上传、预测和手机端流程；这些部分需要后续单独验证。以上建议来自本轮个人体验，尚未开展独立的新用户测试。
